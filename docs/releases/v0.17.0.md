# v0.17.0

**Release Date:** 2026-11-16

## Highlights

- **Encyclopedic support criteria**: opt-in criteria for quoted support, judge confidence and extra sources for
  exceptional claims, with `WikipediaClaimsCriteria()` setting them at an encyclopedic standard of verifiability
- **Refuted claims**: the `refuted` verdict records that a reliable source shows a claim false, so a report can keep
  claims known to be false, such as misconceptions
- **Named standards**: report metadata names the standard the claims were judged against

## Overview

Checking claims for encyclopedia-style attribution needs two things the claims package lacked: a way to say how a
verified claim must be supported, and a way to record a claim shown false. Both are added here as optional fields and
opt-in criteria, so existing reports, decisions and lint output are unchanged unless a report opts in.

## New Features

### Support criteria

```go
report.Criteria = claims.WikipediaClaimsCriteria()
claim.Exceptional = true
claims.SupportShortfalls(claim, report.Criteria) // e.g. ["minSupportConfidence"]
```

| Criterion | A verified claim needs |
|---|---|
| `RequireQuotedSupport` | A quoted `supports` passage with a source |
| `MinSupportConfidence` | A judge confidence at least this level |
| `ExceptionalMinSources` | For a claim marked `Exceptional`, quoted support from this many distinct sources |

`EvaluateClaims` counts claims falling short with those lacking corroboration. `Lint` reports
`verified-requires-quoted-support`, `verified-low-confidence` and `verified-exceptional-needs-sources`.

### Refuted verdict

`refuted` means a reliable source shows the claim false. It blocks publication, is counted in `Counts.Refuted`, needs a
quoted `disputes` passage (`refuted-requires-quoted-dispute`), and the HTML report shows it.

### Standard in report metadata

`ClaimsMetadata.Standard` names the standard and version the claims were judged against, as `<name>@<version>`.

## Compatibility

All changes are additive. The new criteria are off at their zero values, and the new fields are omitted when unset.
The JSON Schema and TypeScript types are regenerated with the new fields.
